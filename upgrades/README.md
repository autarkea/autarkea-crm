# 📦 Каталог миграций-дельт (upgrades/)

Дельты — это **аддитивные** изменения схемы установленной у клиента CRM:
новые колонки, таблицы, опции селектов, связи. Они применяются движком
`upgrade.sh` поверх живой базы **без потери данных клиента**.

## Правила (не нарушать)

1. **Только аддитивность.** Дельта добавляет недостающее и никогда не удаляет
   существующее (колонки, данные, чужие правки клиента).
2. **Идемпотентность.** Повторный запуск дельты безопасен: если колонка/опция
   уже есть — дельта просто пропускает шаг. Ядро `modules/*.sh` уже так работает.
3. **Нумерация.** Имя файла: `U<NNN>_<короткое_имя>.sh`, номер строго растёт.
   Движок применяет только дельты с номером больше текущей версии схемы.
4. **Одна дельта = одна фича.** Не смешивать: «добавил колонку + поменял селект»
   лучше двумя дельтами, чем одной. Это упрощает откат и понимание.
5. **Автобэкап.** Каждая дельта должна полагаться на автобэкап `upgrade.sh`,
   но при прямом запуске (`bash upgrades/U001_...sh`) — делать свой бэкап.
6. **Версия.** В конце дельта **НЕ** пишет версию — это делает движок `upgrade.sh`
   (один источник правды). При прямом запуске — просто выполняется.
7. **Структура БД.** Прямые SQL — только через `modules/*.sh` или с теми же
   предохранителями (транзакция, `.bail on`, проверка существования).
8. **После дельты** — обновить `shared/columns.js` (`generate-columns-map.sh`),
   если появились новые колонки, и задокументировать изменение.

## Шаблон дельты

```bash
#!/bin/bash
# upgrades/U001_имя-фичи.sh
# Что делает: ...
# Целевая версия: 1
set -euo pipefail

NOCO_DB="${NOCO_DB:-/mnt/data/nocodb-data/noco.db}"
cd "$(dirname "${BASH_SOURCE[0]}")/.."

echo "📦 U001: ..."

# Пример: добавить колонку (идемпотентно — add-column сам проверит)
bash modules/add-column.sh "Проекты" "Новая колонка" "TEXT" "Описание" || true

echo "✅ U001 завершена"
```

## Запуск

```bash
bash upgrade.sh                  # применить все недостающие дельты (безопасно)
bash upgrade.sh --dry-run        # показать план, ничего не менять
bash upgrades/U001_имя.sh        # одна дельта вручную (с автобэкапом modules)
```

> ⚠️ **«Большой скачок» (v4.46.0):** если клиент обновляется с очень старой версии,
> префлайт `upgrade.sh` сканирует `upgrades/` ДО `git pull` — новые дельты, которые
> приезжают вместе с кодом, в первый проход не попадают (симптом: «версия схемы не
> менялась» при уже обновлённом коде). С v4.46.0 `upgrade.sh` догоняет их шагом 5.5
> (реконсиляция) в том же запуске. Если апдейт уже был сделан старой версией
> скрипта — просто запусти `bash upgrade.sh` повторно: дельты идемпотентны,
> применятся недостающие и запишется актуальная версия схемы.
